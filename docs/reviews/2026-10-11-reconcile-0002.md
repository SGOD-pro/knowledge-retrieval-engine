# Review: Reconciliation for Workspace Authorization and Boundary Isolation (0002)

**Date**: October 11 2026
**Reviewed by**: Antigravity
**Scope**: 0002 blocker investigation and resolution
**Verdict**: Reconciled and Verified

## Summary

This review records the verification of fixes for the blockers reported against specification 0002.
All reported blockers have been investigated and resolved:
1. Hardcoded test fixtures in `backend/src/api/workspace_boundary_routes.py` were moved into `backend/tests/boundary_test_fixtures.py`. Production routes now inject production dependencies (`RedisCacheAdapter`, `ProductionExecutionEngine`, and `get_workspace_boundary_repo`) via FastAPI `Depends`.
2. Synchronous DynamoDB calls and backoff retries no longer run on the async request thread. FastAPI route endpoints and security dependencies are synchronous `def` callables dispatched to worker thread pools. Asynchronous strategies and services offload synchronous table store and document parsing operations using `loop.run_in_executor`.
3. Test suite imports execute cleanly with proper path configuration.

## Blocker Investigation and Resolutions

### 1. Test fixtures in production routes
* **Investigation**: `backend/src/api/workspace_boundary_routes.py` previously imported and instantiated `ControlledFixtureExecutionEngine` and `InMemoryCacheStore` directly.
* **Resolution**: Fixtures were relocated to `backend/tests/boundary_test_fixtures.py`. Production adapters `ProductionExecutionEngine` and `RedisCacheAdapter` were implemented in `backend/src/api/boundary_adapters.py`. Routes inject these dependencies via `Depends(get_cache_store)` and `Depends(get_execution_engine)`. Test suites override these dependencies via `app.dependency_overrides`.

### 2. Blocking sleep in DynamoDB table store
* **Investigation**: `DynamoDBTableStore.write_row_batch_with_checkpoint` uses exponential backoff with `time.sleep()`. When called from an `async def` context on the ASGI event loop, this would stall concurrent request processing.
* **Resolution**: Rather than swapping `time.sleep` with `asyncio.sleep` (which would violate the synchronous `TableStore` protocol and break synchronous callers), we followed the existing execution pattern:
  * Application routes in `workspace_boundary_routes.py` are declared as synchronous `def` functions, which FastAPI executes in worker thread pools.
  * The authentication dependency `require_auth_context` is declared as a synchronous `def` function, which FastAPI runs in a thread pool.
  * `StructuredTableStrategy.retrieve` uses `loop.run_in_executor` to execute `self.service.execute` in a thread pool.
  * `DocumentsService.ingest_direct` uses `loop.run_in_executor` to execute document parsing and table store writes in a thread pool.
  * `QueryService.execute_query_stream` uses `loop.run_in_executor` to execute queries in a thread pool.

### 3. Regression test imports
* **Investigation**: `backend/tests/test_fix7_idor_regression.py` required path injection to avoid `ModuleNotFoundError` during independent invocation.
* **Resolution**: `sys.path.insert(0, str(Path(__file__).parent.parent / "src"))` was added, ensuring reliable standalone execution.
