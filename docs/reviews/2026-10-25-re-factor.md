## Minor
### 🟡 Bounding top level sections in summary overflow, `backend/src/db/page_index_repo.py:320`
**Problem**: When section hierarchy exceeds forty percent of the storage threshold, the repository retains all level one sections in the summary. If an unusual document contains hundreds of top level sections, the summary could still approach storage bounds.
**Why it matters**: A document with an extreme number of top level headings might challenge the 250KB inline threshold.
**Suggested fix**: Cap the retained top level sections in the summary to fifty elements when overflow occurs, since full section detail is already preserved in S3.

### 🟡 Event loop shutdown resilience in concurrency controller, `backend/src/services/retrieval/page_index_lookup.py:137`
**Problem**: The thread pool task releases the worker slot via call soon threadsafe on the running loop without catching runtime errors during process exit.
**Why it matters**: If worker threads complete while the asyncio loop is closing down, an unhandled runtime error could appear in shutdown logs.
**Suggested fix**: Wrap the threadsafe callbacks in a try block that catches runtime error when the event loop is closed.

### 🟡 Targeted chunk filtering by page number, `backend/src/services/langgraph_pipeline.py:346`
**Problem**: Chunks for a document are retrieved in full before filtering to candidate pages in memory.
**Why it matters**: For large documents with hundreds of pages, fetching all chunks into memory uses unnecessary allocations.
**Suggested fix**: In a future optimization slice, pass candidate page numbers directly to repository queries to load only the chunks on matched pages.
