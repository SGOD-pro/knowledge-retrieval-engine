### 1. Strongly Consistent Base Table Read for Reservation Recovery
* Problem closed: Previously, [`DynamoDBOkfRepository.get_manifest`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/db/okf_repo.py#L918-L940) invoked `table.get_item` without specifying `ConsistentRead=True`. In DynamoDB, default reads from the base table are eventually consistent, which created a window where a newly written attempt reservation or manifest write might not be visible immediately after a worker restart, potentially authorizing a fresh budget erroneously.
* Implemented fix: [`DynamoDBOkfRepository.get_manifest`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/db/okf_repo.py#L918-L940) now accepts `consistent_read: bool = True` (defaulting to `True` across all repository implementations) and passes `ConsistentRead=consistent_read` to DynamoDB `table.get_item`. Budget recovery in [`get_or_create_document_budget`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/ingestion/okf_builder.py#L210-L260) and idempotency checks in [`OkfBuilder.extract_and_persist`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/ingestion/okf_builder.py#L900-L965) explicitly request strongly consistent reads.
* Fail closed budget recovery: Catching [`StorageUnavailableError`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/schemas/contracts/boundary.py#L11-L15) on storage failure continues to mark `prior_exhausted = True` and `prior_reason = f"storage_read_failed ({e})"`, ensuring zero provider calls.
* Clean authorization for missing items: When an item is not found in storage, `resp.get("Item")` is `None`. [`DynamoDBOkfRepository.get_manifest`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/db/okf_repo.py#L918-L940) returns `None` without raising an exception, cleanly authorizing a fresh budget with `calls_made = 0` and `can_call() == True`.
