### 4. Mathematical Evidence for Byte Based Token and Framing Bounds
* Lower bound invariant for byte level BPE: In [`count_request_tokens`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/ingestion/okf_builder.py#L652-L690), docstrings record the formal mathematical invariant for Claude 3 Haiku, Claude 3.5 Sonnet, and Claude 3 Sonnet. In byte level BPE tokenizers, every base token represents at least 1 byte of UTF 8 input, while merged tokens represent 2 or more bytes. Thus, for any UTF 8 text T, the token count N satisfies N <= |T|_bytes.
* Envelope framing safety margin: Envelope JSON structures, system tags, and delimiter tokens consume fewer than 16 special tokens. Adding 32 framing tokens establishes a provable upper bound that character heuristics cannot match.
* Explicit assumptions and fail closed validation: Non BPE models, synthetic expansion tokenizers, or unverified architectures do not satisfy this invariant. Unsupported model identifiers raise `ValueError` immediately, failing closed with zero provider calls.
