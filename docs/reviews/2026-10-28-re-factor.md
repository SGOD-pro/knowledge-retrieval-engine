## Summary

The uncommitted changes on branch `re-factor` fulfill all five architectural and correctness requirements across ingestion budgeting, concurrency bounding, crash resilience, and regression safety. The implementation replaces naive character heuristics with a mathematically defensible token upper bound using UTF 8 byte length plus 32 framing tokens for supported Claude 3 models. It introduces [`OkfProviderConcurrencyController`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/ingestion/okf_builder.py#L657) to bound provider concurrency across documents to 2 workers and 4 queued callers while retaining worker capacity on caller timeouts until background work completes. In flight attempt reservations persist to durable storage prior to provider calls, ensuring single worker crashes do not reset document version budgets upon replay. All existing baselines, scope constraints, and relational grounding checks remain intact. The full backend test suite passes with 492 passing tests and zero failures.

### 1. Defensible Input Token Bound
* Complete request evaluation: The function [`count_request_tokens`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/ingestion/okf_builder.py#L633) evaluates the entire request payload including system instructions, user content blocks, XML tags, and 32 envelope framing tokens.
* Proven byte upper bound: For supported Claude 3 models using byte level BPE tokenization, each token consumes at least 1 byte of UTF 8 input text. Therefore, byte length plus 32 framing tokens establishes a proven upper bound that cannot underestimate high density or punctuation heavy sequences where character heuristics fail.
* Fail closed model validation: `SUPPORTED_OKF_MODELS` defines the verified configuration set (`anthropic.claude-3-haiku-20240307-v1:0`, `anthropic.claude-3-5-sonnet-20240620-v1:0`, `anthropic.claude-3-sonnet-20240229-v1:0`). Any unverified model configuration raises a `ValueError` in [`count_request_tokens`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/ingestion/okf_builder.py#L633) and causes [`OkfBuilder._invoke_bedrock_extraction`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/ingestion/okf_builder.py#L1335) to fail closed immediately with zero provider calls.
* Verified in [`backend/tests/test_okf_correctness_regressions.py`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/tests/test_okf_correctness_regressions.py#L1301) by `test_token_bound_never_underestimates_and_catches_heuristic_failures`.

### 2. Provider Call Concurrency Across Documents
* Bounded cross document concurrency: [`OkfProviderConcurrencyController`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/ingestion/okf_builder.py#L657) limits simultaneous provider calls across all documents to a maximum of 2 concurrent workers and sheds load when queue depth exceeds 4 pending callers.
* Capacity retention on caller timeout: When a caller document deadline expires, the worker semaphore slot and thread pool capacity are retained until the underlying provider call finishes executing in the background. Caller timeout never releases provider slots prematurely, preventing cascading overload on downstream providers.
* Verified in [`backend/tests/test_okf_correctness_regressions.py`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/tests/test_okf_correctness_regressions.py#L1365) by `test_concurrent_provider_calls_bounded_across_documents` and `test_provider_timeout_capacity_retention_blocks_immediate_new_calls`.
