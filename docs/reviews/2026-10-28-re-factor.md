## Reconciliation of previous claims

The previous review [`docs/reviews/2026-10-26-re-factor.md`](file:///home/swyra/projects/knowledge-retrieval-engine/docs/reviews/2026-10-26-re-factor.md) noted strong progress but contained three latent gaps that this changeset resolves:

1. **Relational grounding precision**: The previous review claimed relational grounding rejected unsupported relationships beyond entity and value co occurrence. However, when multiple financial metrics appeared within a single sentence, the previous code could bind a value to an unrelated metric. The updated logic in [`validate_assertion_grounding`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/ingestion/okf_builder.py#L424) resolves this counterexample by enforcing clause boundaries, proximity distance, and intervening metric checks.
2. **Snapshot authorization boundary**: The previous review noted fail closed semantics, but the retrieval code retained a fallback allowing manifests to authorize candidates when snapshot data was missing. The updated [`OkfRetriever`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/services/retrieval/okf_retriever.py#L182) removes `has_snapshot_data` entirely, ensuring that missing or empty snapshots always yield zero OKF candidates and immediately defer to baseline retrieval.
3. **Provider request budgeting and deadline bounding**: The previous review did not address token budgeting bounds or provider call blocking times. Token estimation previously counted only user prompt characters. The updated implementation computes a conservative upper bound across the complete provider request via [`count_request_tokens`](file:///home/swyra/projects/knowledge-retrieval-engine/backend/src/ingestion/okf_builder.py#L623) and enforces elapsed document deadlines during blocking calls using bounded thread futures.
