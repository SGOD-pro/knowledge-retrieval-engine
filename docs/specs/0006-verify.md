## Acceptance criteria coverage
- AC-1: Ingestion extracts and persists typed OkfEntityRecord and OkfPropertyAssertion records per document version for text PDF and tabular CSV files. For CSV tables, OKF extracts curated table schemas, column names, and data types deterministically with zero model tokens.
- AC-2: Extracted assertions are validated against authorized active chunks and locators before persistence. Unsupported claims and non matching values are rejected as hallucinated claims and omitted from storage.
- AC-3: (Partially satisfied; cross process coordination and framing allowance kept open as documented limitations) Ingestion extraction enforces strict resource bounds (maximum 2 Bedrock calls, 2000 input tokens per call, 4000 total input tokens, 600 output tokens per call, 1200 total output tokens, and 10s deadline). Idempotency keys prevent repeated calls upon document re ingestion. Provider call concurrency across documents is bounded with capacity retention on caller timeout. Attempt reservations persist to durable store before calls, failing closed with zero provider calls on write or read persistence failure. Budget recovery uses strongly consistent base table reads (ConsistentRead=True in DynamoDB) to eliminate replication lag upon restart or replay. In process locks coordinate threads within a single Python process; cross process coordination across multiple processes on one host or across multiple hosts remains an open limitation pending distributed leasing infrastructure or atomic conditional writes. The 32 token envelope framing allowance remains an unverified assumption requiring direct provider and model tokenizer evidence. Baseline publication completes independently per ADR-001.
- AC-4: Stable assertion identities preserve distinct provenance. Conflicting values from differing documents persist under unique assertion IDs and return property_state conflicting.
- AC-5: Same name entities across differing documents retain distinct document scoped identifiers. Matching multiple documents returns entity_state ambiguous without premature entity merging.
- AC-6: OKF storage and lookups are partitioned strictly by workspace identifier. GSI1 index queries resolve entities without workspace scans, returning zero cross tenant leakage.
- AC-7: Active deletion tombstones in WorkspaceBoundaryRepository filter out assertions belonging to deleted source documents immediately inside worker tasks.
- AC-8: OKF lookups enforce 50ms caller deadlines and bounded concurrency worker admission (maximum 4 workers, maximum 8 queued submissions), retaining capacity until underlying storage finishes.
- AC-9: (Slice 2) Candidate chunks pool into reciprocal rank fusion with calibrated weight (1.15) and fast path bypass.
- AC-10: Scoped retrieval queries exclusively through workspace partitioned tables, leaving legacy unpartitioned tables untouched and excluded by construction.
- AC-11: DocumentSnapshot exposes okf_status, okf_entities_count, and okf_properties_count without requiring dedicated administrative HTTP endpoints.
- AC-12: (Slice 2) Offline ablation suite evaluates candidate recall, precision, and latency with OKF enabled versus disabled.
