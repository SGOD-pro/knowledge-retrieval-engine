## Acceptance criteria coverage
- AC-1: Ingestion extracts and persists typed OkfEntityRecord and OkfPropertyAssertion records per document version for text PDF and tabular CSV files. For CSV tables, OKF extracts curated table schemas, column names, and data types deterministically with zero model tokens.
- AC-2: Extracted assertions are validated against authorized active chunks and locators before persistence. Unsupported claims and non matching values are rejected as hallucinated claims and omitted from storage.
- AC-3: Ingestion extraction enforces strict resource bounds (maximum 2 Bedrock calls, 2000 input tokens per call, 4000 total input tokens, 600 output tokens per call, 1200 total output tokens, and 10s deadline). Every physical dispatch attempt, including throttling retries, acquires a separate atomic durable reservation before calling the model. SDK level retries are disabled. Reservations cover estimated prompt tokens and maximum output tokens, preserving separate prompt and output ceilings across restarts without integer division heuristics. Ceilings are strictly enforced on initial absent ledger reservations and subsequent reservations across DynamoDB, SQLite, and InMemory stores. Idempotent reconciliation tracks completed fence tokens with atomic conditions to prevent duplicate or stale double counting. Monotonic fence tokens prevent stale workers from publishing assertions while retaining accounted spend. Manifest writes enforce atomic publication fencing via DynamoDB transactions and SQLite conditional statements, preventing stale workers from overwriting published state or exposing assertions even when paused after fence validation. In flight attempt manifests and failure manifests enforce fence tokens to protect active states. Unfenced manifest writes are prevented from overwriting active leases or published ready manifests across DynamoDB, SQLite, and InMemory repositories. Readiness via has_ready_okf is authoritatively bound to exact workspace, document, and version manifests with consistent reads, rejecting false readiness from stale assertions or non ready records. The 99 item DynamoDB transaction publication boundary is verified against DynamoDB Local, ensuring oversized transactions fail open per ADR-001 without partial writes. Large publications with 100 or more items stage payload items first into distinct publication scoped keys before committing visibility atomically via a two item transaction, verified against crashes, lease acquisitions, and concurrent workers. Same version republication scopes entity and assertion keys to publication identifiers, ensuring retrieval queries return only current facts without query limit dilution from stale records. Deletion of old DynamoDB records is deferred to maintain reader safety. Storage and token counting failures cause zero provider dispatches and fail open to preserve baseline ingestion availability. Bedrock count_tokens is strictly required before provider dispatch, failing closed on missing, malformed, or zero token counts. Conditional and update expressions are verified against real DynamoDB Local container. Live AWS endpoint verification remains pending live test execution.
- AC-4: Stable assertion identities preserve distinct provenance. Conflicting values from differing documents persist under unique assertion IDs and return property_state conflicting.
- AC-5: Same name entities across differing documents retain distinct document scoped identifiers. Matching multiple documents returns entity_state ambiguous without premature entity merging.
- AC-6: OKF storage and lookups are partitioned strictly by workspace identifier. GSI1 index queries resolve entities without workspace scans, returning zero cross tenant leakage.
- AC-7: Active deletion tombstones in WorkspaceBoundaryRepository filter out assertions belonging to deleted source documents immediately inside worker tasks.
- AC-8: OKF lookups enforce 50ms caller deadlines and bounded concurrency worker admission (maximum 4 workers, maximum 8 queued submissions), retaining capacity until underlying storage finishes.
- AC-9: (Slice 2) Candidate chunks pool into reciprocal rank fusion with calibrated weight (1.15) and fast path bypass.
- AC-10: Scoped retrieval queries exclusively through workspace partitioned tables, leaving legacy unpartitioned tables untouched and excluded by construction.
- AC-11: DocumentSnapshot exposes okf_status, okf_entities_count, and okf_properties_count without requiring dedicated administrative HTTP endpoints.
- AC-12: (Slice 2) Offline ablation suite evaluates candidate recall, precision, and latency with OKF enabled versus disabled.
